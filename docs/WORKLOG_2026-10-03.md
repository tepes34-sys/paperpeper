## 3. think

A proposal now defines seven review principles for numerical contracts:

1. State each field's meaning, unit, and accepted range.
2. Validate the type, format, and finiteness of inputs actually used.
3. Own the calculation context and explain it against input limits.
4. Specify where and why rounding occurs.
5. Separate exact numerical equality from output formatting.
6. Define errors, partial results, and completion stages.
7. Track version, rationale, adoption, and validation evidence.

The proposal initially targets paperA and TCC. It does not impose one precision, serializer, helper, or exit-code policy across projects. It remains **proposed**, with no newly approved decision or common invariant claimed.

Approval of a principle and verified implementation in each project are separate gates. Work on a local defect or an independent product need not wait for all other projects to finish.
