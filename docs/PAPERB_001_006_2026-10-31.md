## Defect and repair

001 accepted repeated column names after whitespace normalization. The CSV reader silently kept the later value, potentially changing transaction IDs, symbols, quantities or prices.

The candidate rejects duplicate normalized headers before processing any row. Initial cash, empty positions and zero processed rows are retained on file rejection. One regression method covers the five required columns plus an optional note column, each with and without surrounding whitespace. All **12 subtests failed before the repair and passed afterward**. Removing the new guard in a temporary mutant reproduces those assertion failures.

This is one newly found ledger defect of the same type previously repaired in the comparator. It is not a recurrence of an already repaired ledger-header contract. No recurring defect was observed in the executed checks.

Duplicate transaction IDs retain a separate existing behavior: they generate diagnostics while rows still contribute to the diagnostic state. The inspector does not deduplicate or repair financial records, and rerunning it is not a financial idempotency guarantee.
