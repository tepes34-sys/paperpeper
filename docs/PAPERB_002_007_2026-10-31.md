## Repairs in 002

Duplicate column names, including names that become equal after trimming whitespace, silently used the later CSV value. The candidate rejects the ambiguous file before producing a report. A new regression covers the three required columns plus an optional note column, with and without surrounding whitespace.

Malformed P/L text also changed the caller's sticky Decimal error flag and produced trap-dependent diagnostics. Parsing now uses an owned error context, preserving caller state and giving consistent invalid-syntax diagnostics.

Both new regression methods failed before repair, with **11 failing subtests** in total. After repair, 002 passed **10/10** tests. Removing each fix independently produced assertion failures: **two of two reverted-fix mutants detected**.

The existing report ID policy is preserved. Once a nonempty ID passes the column-count check, its first encounter occupies the ID even if that row later fails symbol/P/L validation. A later row with the same ID is excluded. This differs from the comparator's malformed-P/L correction policy; this change does not silently unify those contracts.

The executed scope found **two new defects, both repaired, and zero recurring defects**. They are cross-module findings of a previously observed failure type, not recurrences of an already repaired report contract.
